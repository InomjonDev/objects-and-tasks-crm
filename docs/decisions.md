# Решения и допущения

- Все постановщики равноправны: каждый видит и управляет всеми активными объектами и задачами. Назначить задачу можно только исполнителю.
- Название задачи и объекта, адрес и исполнитель обязательны. Описание задачи можно оставить пустым. Максимальная длина названия — 200 символов, адреса — 500, описания — 10 000, комментария — 2 000. Эти ограничения проверяются и в базе.
- Статус новой задачи задаёт база. Автор, время создания и автор изменения определяются на сервере; клиент не передаёт их в функциях записи.
- Редактирование и переназначение не сбрасывают статус и историю. Предыдущий исполнитель теряет доступ сразу после переназначения; новый получает доступ к существующей истории.
- Удаление мягкое. При удалении объекта скрываются и его задачи. История сохраняется физически, но недоступна через обычный API для скрытых задач. Страница восстановления не предусмотрена.
- История фиксирует создание и смены статусов; журнал всех правок текста и назначений в ТЗ не требуется.
- Возврат на доработку требует непустого комментария после удаления крайних пробелов. При принятии комментарий необязателен; API поддерживает его, интерфейс использует комментарий для возврата.
- При двух одновременных действиях на одном статусе проходит одно. Второй запрос получает ошибку о сменившемся статусе, интерфейс обновляет данные.
- Интерфейс поддерживает русский и английский; выбор сохраняется в браузере. Пользовательские данные не переводятся. Даты показываются в выбранной локали и часовом поясе браузера. База хранит время с часовым поясом.
- Небольшой демо-набор загружается целиком, максимум 1 000 видимых строк на таблицу. При росте данных нужны пагинация и загрузка истории по конкретной задаче.
- Supabase Free не включает проверку паролей по базе утечек. Это отражено в результатах Advisors; для демо используются случайные длинные пароли и закрытая регистрация.
- Нет вложений, уведомлений, realtime, отчётов, редактирования ролей и удаления сотрудников, восстановления удалённых записей и видео. Для объяснения выбран текст.
- Использован ИИ. Перед собеседованием стоит разобрать миграцию, RLS, разделение публичных и приватных функций и тесты прямого API: это основные решения, которые нужно уметь объяснить самостоятельно.

Фактические результаты проверок и развёртывания фиксируются отдельно в `docs/verification.md` после выполнения.

Дополнительно по запросу добавлены профиль, редактирование собственного имени и создание сотрудников постановщиками. Это расширение исходного тестового задания. Имена и роли существуют в базе, а не в доверяемых клиентских метаданных. Email сотрудников не добавлен в общедоступную таблицу профилей.
