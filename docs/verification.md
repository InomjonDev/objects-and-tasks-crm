# Проверка результата

Проверено 5 ноября 2026 года.

- Рабочее приложение: https://objects-and-tasks-crm-one.vercel.app
- Репозиторий: https://github.com/InomjonDev/objects-and-tasks-crm
- Supabase: отдельный Free проект `mrhpktvjhpamhlujccyp`. Миграции применены и записаны в журнал миграций. Открытая регистрация отключена, Site URL настроен на адрес приложения.
- Vercel: Hobby/Free, сборка из исходников через официальный API. Публичные параметры Supabase и настройка Corepack заданы в окружении проекта; административного ключа там нет.

## Автоматические проверки

- Шесть тестов переводов, интерфейсных переходов и валидации сотрудников — пройдены.
- 150 проверок миграций и доступа в изолированном PostgreSQL — пройдены, включая 100 комбинаций статусов и четырёх пользователей с двумя разными ролями.
- 47 прямых проверок API облачного Supabase — пройдены: закрытая регистрация, изоляция задач, запрет прямых изменений, закрытая схема `private`, переходы, обязательный комментарий, конкурирующие запросы, защищённая история, переназначение и мягкое удаление.
- 29 дополнительных API-проверок профиля и создания сотрудников — пройдены. Проверены обе создаваемые роли, 401/403, дубли email, некорректный ввод, закрытый список сотрудников, редактирование имени и невозможность повышения роли через метаданные.
- TypeScript, ESLint, установка по неизменяемому Yarn lockfile и production build — пройдены.
- Supabase Security Advisors — замечаний к таблицам, RLS и функциям приложения нет. Осталось одно платформенное предупреждение `auth_leaked_password_protection`: проверка паролей по базе утечек недоступна на Free и требует Pro или выше ([документация Supabase](https://supabase.com/docs/guides/auth/password-security)). Тариф не менялся; демо-пароли сгенерированы случайно.
- В кандидатах файлов репозитория не обнаружены административный ключ и пароли демо-пользователей. Локальные файлы окружения и доступов исключены из Git и загрузки Vercel.

## Проверка в браузере

Chromium, ширина 1280 и 375 пикселей:

- Вход постановщика и двух исполнителей в опубликованном приложении; выход и сообщение при неверном пароле.
- Создание и редактирование объекта и задачи, выбор объекта и исполнителя.
- Цикл задачи: новая → в работе → на проверке → на доработке → в работе → на проверке → принята. При возврате пробельный комментарий не позволяет подтвердить действие.
- После переназначения предыдущий исполнитель теряет доступ по прямой ссылке. Новый видит задачу и сохранённую историю, принятый статус не сбрасывается.
- Мягкое удаление задачи и объекта через подтверждение. Временные проверочные записи скрыты, история остаётся в базе.
- Обновление вложенных URL проекта и задачи на Vercel работает.
- На ширине 375 пикселей страница не имеет горизонтального переполнения, таблица прокручивается внутри контейнера. Диалог задачи помещается в экран 375 × 667.

Для проверки использовались отдельные временные записи. Основной демо-набор: один постановщик, два исполнителя, три объекта, восемь задач во всех пяти статусах.

## Ограничения проверки

Safari, Firefox, реальные телефоны и нагрузочные испытания не запускались. Локальный экспериментальный native-стек Supabase не удалось запустить; миграции проверены отдельно в PostgreSQL, а API и авторизация — в настоящем облачном Supabase.

Сборка предупреждает об одном JS-файле около 581 КБ, примерно 176 КБ с gzip. Разделение загрузки по маршрутам не добавлялось для небольшого тестового приложения. На таблицу загружается максимум 1000 видимых записей; для большего набора нужна пагинация.

Оценка времени реализации, проверки и развёртывания — примерно 1–1,5 часа, включая сетевые задержки установки. Точный таймер отдельно не вёлся.

## Дополнительная проверка интерфейса

На localhost проверены английский и русский, сохранение выбора языка после перезагрузки, перевод форм, статусов, доступных действий и дат. Пользовательские имена и содержимое задач остаются исходными. Проверен show/hide-переключатель пароля: координаты кнопки и поля совпадают по вертикали, в том числе во время нажатия. Удалён текст о байтах из подсказки.

Профиль проверен для постановщика и нового исполнителя. Проверены создание сотрудника через форму, вход созданного исполнителя, редактирование собственного имени, отсутствие списка сотрудников у исполнителя, скелетоны во время загрузки, shimmer 1.8 секунды и его отключение при reduced motion. На ширине 375 px страница профиля не имеет горизонтального переполнения. Проверены светлая и тёмная темы. Временные аккаунты тестов удаляются адресно; созданные пользователем сотрудники сохраняются.

## Сверка с техническим заданием

При повторной проверке 5 ноября 2026 года в опубликованной базе: три активных объекта, девять активных задач, два постановщика и три исполнителя. Есть задачи во всех пяти статусах: три новые, две в работе, одна на проверке, две приняты и одна на доработке. Пользовательские дополнения к исходному демо-набору сохранены.

Подтверждено чтением настроек и прав базы: открытая регистрация отключена, RLS включён на `profiles`, `projects`, `tasks` и `task_history`, у роли `authenticated` нет прямых прав INSERT, UPDATE и DELETE для истории. Статические проверки ролей, полей, экранов и переходов соответствуют таблице в README. Код приложения при этой сверке не менялся.

Само сообщение рекрутеру из приложения или скриптов не отправлялось. Сообщение о начале работы и согласование времени сдачи относятся к общению с рекрутером и этой проверкой не подтверждаются.
